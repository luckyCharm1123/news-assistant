# n8n Agent 提示词使用指南

## 文件说明

### 1. `n8n_agent_prompt.md` - 基础版（当前使用）
- **功能**：获取新闻、筛选并保存精选新闻
- **适用场景**：简单的新闻收集任务
- **特点**：
  - 每次获取最近2小时新闻
  - 保存最多15条精选新闻
  - 不处理历史数据
  - 不降低原始新闻关注度

### 2. `n8n_agent_prompt_v2.md` - 完整版（推荐）
- **功能**：获取新闻 + 去重 + 标记已处理
- **适用场景**：生产环境的完整工作流
- **特点**：
  - ✅ 获取并保存精选新闻
  - ✅ 自动识别并合并相似新闻
  - ✅ 降低已处理原始新闻的关注度（避免重复获取）
  - ✅ 保持精选新闻列表整洁

### 3. `n8n_agent_dedup_prompt.md` - 专用去重组件
- **功能**：仅处理历史精选新闻的去重和清理
- **适用场景**：定期清理任务（如每周一次）
- **特点**：
  - 专注于合并相似新闻
  - 降低所有历史精选关联的原始新闻关注度
  - 不获取新新闻

## 推荐的工作流架构

### 方案A：单Agent完整流程（推荐）
```
┌─────────────────────────────────────┐
│  n8n Workflow (使用 v2 提示词)      │
│                                     │
│  1. 获取最近2小时新闻               │
│  2. 筛选并保存精选新闻              │
│  3. 合并相似历史精选（如果>50条）    │
│  4. 降低已处理新闻关注度            │
└─────────────────────────────────────┘
```

**优点**：
- 一个工作流完成所有任务
- 自动维护数据质量
- 避免重复获取新闻

**配置**：
- 调度频率：每2小时执行一次
- 提示词文件：`n8n_agent_prompt_v2.md`

### 方案B：双Agent分离流程
```
┌──────────────────────┐     ┌──────────────────────────┐
│  Workflow 1 (主任务)  │     │  Workflow 2 (定期清理)    │
│                      │     │                          │
│  - 获取新闻          │     │  - 获取所有历史精选      │
│  - 保存精选          │     │  - 合并相似新闻          │
│  - 降低关注度        │     │  - 降低关注度            │
│                      │     │                          │
│  频率: 每2小时       │     │  频率: 每周一次          │
│  提示词: v2版        │     │  提示词: dedup版         │
└──────────────────────┘     └──────────────────────────┘
```

**优点**：
- 主任务快速执行（无需检查历史）
- 定期深度清理，保持数据质量
- 灵活的调度策略

**配置**：
- Workflow 1：每2小时，使用 `n8n_agent_prompt_v2.md`（跳过合并步骤）
- Workflow 2：每周一次，使用 `n8n_agent_dedup_prompt.md`

## MCP工具说明

### 已有工具
1. `get_recent_news(hours)` - 获取最近N小时的新闻
2. `batch_add_curated_news(news_list)` - 批量保存精选新闻
3. `get_curated_news(limit, offset)` - 获取所有精选新闻
4. `merge_curated_news(keep_id, merge_ids, merged_title, merged_summary)` - 合并相似新闻
5. `batch_decrease_popularity(news_ids, decrease_amount)` - 批量降低关注度

### 工具使用流程

#### 完整流程示例
```python
# 1. 获取新新闻
recent_news = get_recent_news(hours=2)

# 2. 筛选并保存
selected = filter_news(recent_news)
batch_add_curated_news(news_list=selected)

# 3. 获取历史精选（可选）
all_curated = get_curated_news(limit=200)

# 4. 合并相似新闻
merge_curated_news(
    keep_id=10,
    merge_ids=[15, 18],
    merged_title="【新能源车】特斯拉上海工厂产量破百万"
)

# 5. 降低已处理新闻关注度
source_ids = [n['source_news_id'] for n in all_curated]
batch_decrease_popularity(news_ids=source_ids, decrease_amount=5)
```

## 关键参数说明

### decrease_amount（降低关注度）
- **推荐值**：5
- **原因**：
  - 热门新闻阈值通常是 `popularity >= 3`
  - 降低5个单位可以确保新闻不会被重复获取
  - 即使新闻之前被多次关注，降低后也会低于阈值

### 合并新闻数量
- **单次合并**：建议不超过5条记录
- **总精选数量**：建议保持在50条以下
- **清理频率**：当超过50条时触发清理

## 切换提示词的步骤

### 从基础版升级到完整版
1. 在 n8n 中编辑 AI Agent 节点
2. 将 `n8n_agent_prompt.md` 的内容替换为 `n8n_agent_prompt_v2.md`
3. 保存并测试工作流

### 验证升级成功
检查日志是否包含：
- ✅ "成功保存X条精选新闻"
- ✅ "合并了X组相似新闻"
- ✅ "降低了X条原始新闻的关注度"

## 常见问题

### Q1: 为什么要降低原始新闻的关注度？
**A**: `get_recent_news` 工具会返回高关注度的新闻（popularity >= 3）。如果不降低关注度，相同的新闻会在下次执行时被重复获取，导致：
- 精选新闻列表出现大量重复
- 浪费处理资源
- 降低信息质量

### Q2: 合并新闻后，原始记录会删除吗？
**A**: 不会。合并操作会：
- 保留主记录（keep_id）
- 标记被合并记录（设置 is_merged=1）
- 被合并记录不会再出现在 `get_active_curated_news` 的结果中
- 但数据仍然保留在数据库中，便于追溯

### Q3: 如何判断是否需要合并？
**A**: 以下情况建议合并：
- 相同公司的同一事件
- 相同政策的不同报道
- 标题关键词重合度 > 70%
- 时间接近（同一天或相邻天）

### Q4: 执行频率建议？
**A**:
- **主任务（获取新闻）**：每2小时一次
- **完整清理（合并+降权）**：每天一次
- **深度清理（只合并）**：每周一次

## 监控指标

建议在 n8n 中设置以下监控：

### 数据质量指标
- 精选新闻总数（建议 < 100）
- 平均相似度（建议 < 30%）
- 重复率（建议 < 10%）

### 执行效果指标
- 每次新增精选数量（5-15条为佳）
- 合并操作频率（不应过于频繁）
- 降低关注度成功率（应 > 95%）
